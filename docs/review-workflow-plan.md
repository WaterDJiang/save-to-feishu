# 回顾工作流优化计划

更新时间：2026-06-15

## 目标

让用户在保存时明确设置回顾时间，并能在“最近保存与待回顾”中心快速管理回顾状态。

## 用户问题

- “下次回顾”目前藏在“更多整理信息”折叠区，不容易发现。
- 最近保存记录不能快速加入待回顾。
- 待回顾记录不能从列表中移除。

## 交互规则

1. 保存页：
   - 将“下次回顾”提升为常驻区域；
   - 保留日期选择；
   - 提供“今天”“明天”“7 天后”“清除”快捷操作。
2. 最近保存：
   - 未到期或未设置回顾日期的记录显示“加入待回顾”；
   - 点击后把回顾日期设为今天，立即出现在待回顾列表。
3. 待回顾：
   - 提供“移出待回顾”操作；
   - 操作只清除本地回顾日期；
   - 不删除最近保存记录，不删除飞书记录或 Markdown 文件。

## 组件化方案

- 在保存记录工具中统一日期 key、到期判断和回顾日期更新逻辑。
- 在存储服务中新增专用回顾状态更新接口，不复用成功保存接口，避免错误增加评分里程碑次数。
- 在现有 `SavedContentLibrary` 中复用统一列表操作样式。
- 新增 `ReviewScheduleField`，集中管理保存页日期输入和快捷日期交互。

## 验收标准

- 保存页无需展开折叠区即可看到“下次回顾”。
- 快捷日期按本地日期生成，不受 UTC 日期偏移影响。
- 最近保存一键加入后立即出现在待回顾。
- 移出待回顾后仍保留在最近保存。
- 回顾状态修改不增加成功保存次数。
- 不运行 npm 本地构建或测试；完成静态差异检查后提醒用户重新加载插件验证。
