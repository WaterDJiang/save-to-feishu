# 首次使用 Markdown 路径优化计划

更新时间：2026-06-20

## 目标

让未连接飞书、未完成任何配置的用户，首次打开插件时同时看见两种保存方式：立即下载 Markdown，或保存到飞书并进入设置完成连接；飞书不是阻塞 Markdown 的前置条件，Markdown 也不被暗示为唯一推荐路径。

## 用户路径

1. 用户首次打开侧栏或弹窗。
2. 页面并列展示“保存到飞书”和“保存 Markdown 到电脑”两个入口，视觉权重一致。
3. 点击“保存到飞书”只进入设置完成凭证和资料库连接；点击“保存 Markdown 到电脑”直接下载 `.md` 文件。
4. Markdown 保存后展示成功反馈；最近保存记录仍只存放在浏览器本地。

## 数据与隐私边界

- 不新增账号、后端请求、权限或行为追踪。
- Markdown 仅在用户主动点击后由浏览器下载到本机。
- 继续复用本地 `savedContents` 保存历史和既有成功保存计数；不新增网页内容上传。
- 连接飞书仍必须由用户主动进入设置并填写自己的凭证。

## 组件化方案

- 新增共享的 `MarkdownFirstSaveCard`：侧栏和弹窗复用同一套首次状态文案、并列双入口及 Markdown 保存反馈。
- 继续复用 `generateMarkdown`、`downloadMarkdown`、`rememberSavedContent` 和 `createSavedContentRecord`；不复制 Markdown 生成或本地保存逻辑。
- 保存方式默认值仅对没有保存方式的本地配置生效：无资料库时归为 Markdown，有既有资料库的旧配置保持飞书优先，避免意外改变老用户习惯。

## 验收标准

- 全新本地配置的默认保存方式为 Markdown。
- 侧栏和弹窗在未配置资料库时均同时提供“保存到飞书”和“保存 Markdown 到电脑”，不以主次按钮暗示用户只能选择其中一种。
- “保存到飞书”只进入设置；“保存 Markdown 到电脑”继续直接下载文件。
- 点击保存后生成 Markdown、写入本地最近保存记录，并反馈成功或失败。
- 不运行 npm 构建或测试；完成后检查类型、导入和差异，并由用户在真实扩展环境验证。
