### 高质量摘录实现设计

- 本轮先实现侧栏中的高质量摘录 MVP，不触碰弹窗、右键和开箱即用飞书建表。
- 摘录来源复用 `extractCurrentPageSnapshot().content.selectedText`，没有选中文本时只提示用户先在网页中选中内容，不做空保存。
- 摘录数据不新增独立保存通道，而是复用现有 `ExtractedPageContent`、`KnowledgeMetadata`、Markdown 生成、飞书保存和最近保存记录：
  - `content.selectedText` 与 `content.content` 写入摘录正文；
  - `metadata.excerpt` 写入摘录正文；
  - `metadata.note` 写入“摘录价值说明/备注”；
  - `metadata.contentType` 用于表达摘录类型，首批复用现有资料类型可承载的值，不新增飞书字段强依赖。
- Markdown 输出需要显式标注这是“摘录”，避免和整篇网页剪藏混淆。
- 最近保存通过标题前缀区分摘录，不新增迁移逻辑，兼容旧记录。

### 高质量摘录 MVP 实际改动

- 侧栏目标页新增“保存选中摘录”入口：
  - 当前页面有选中文本时，可进入摘录整理；
  - 当前页面没有选中文本时，提示用户先在网页中选中内容。
- 摘录整理页新增：
  - 摘录正文编辑；
  - 摘录类型选择：观点、案例、数据、金句、问题、其他；
  - 继续复用标签、摘要、自定义字段、回顾日期、个人备注和原保存按钮。
- 数据模型扩展：
  - `ExtractedPageContent.contentKind` 标识整篇网页或摘录；
  - `ExcerptType` 标识摘录类型；
  - `KnowledgeMetadata.excerptType` 和 `SavedContentRecord.excerptType` 保留摘录类型。
- 最近保存记录区分同一网页的全文记录和摘录记录，避免互相覆盖。
- Markdown 输出新增：
  - `clip_kind`；
  - `excerpt_type`；
  - “摘录正文”区块。
- 飞书字段映射新增 `excerptType` 来源；资料库模板和共享模板允许映射“摘录类型”。
- 帮助文档、插件内帮助和 README 已补充高质量摘录说明。
- 新增 `tests/savedContent.test.ts` 用例，覆盖同一 URL 的全文记录和摘录记录应分开保存。
- 摘录模式下 AI 写入不会替换用户选中的摘录正文，只补充标签、摘要和自定义整理字段。

### 高质量摘录体验修正

- 用户在真实网页中反馈：已经选中文本后，侧栏仍可能提示“请先在网页中选中内容”，说明侧栏捕捉 selection 的路径受焦点切换影响，体验与全文收藏割裂。
- 决策调整：
  - 高质量摘录主路径改为网页选中文本后使用右键菜单；
  - 右键菜单直接读取 Chrome `contextMenus` 提供的 `selectionText`，避免切到侧栏后 selection 丢失；
  - 侧栏不再强化“捕捉选中文本”的主入口，回到整理和管理工作台定位。
- 本轮继续保持所有保存动作由用户主动点击触发，不新增后台爬取、自动采集或遥测。

### 右键摘录实际改动

- 右键菜单新增 selection 场景：
  - “保存选中摘录为 Markdown”；
  - “保存选中摘录到：某个飞书资料库”；
  - “打开设置配置资料库...”。
- 右键保存摘录直接使用 `info.selectionText` 作为摘录正文，并保留原网页标题、链接、保存时间、摘录类型和正文。
- 右键保存到飞书时复用现有 `saveToFeishu`、字段映射、飞书文档生成和最近保存记录，不新增保存通道。
- 右键保存 Markdown 时复用现有 Markdown 生成和最近保存记录，通过当前网页触发下载，不新增 `downloads` 权限。
- 保存完成后在网页右上角显示轻提示，并同步设置扩展图标 badge 成功/失败状态。
- 侧栏目标页不再提供“保存摘录”按钮，改为提示用户在网页中选中文字后直接右键保存，避免切回侧栏导致 selection 丢失。
- README、插件内帮助和 `docs/help.html` 已改为右键摘录路径。
