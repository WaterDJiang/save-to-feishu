# 公众号长文内容提取修复计划

更新时间：2026-06-24

## 目标

修复公众号长文在侧栏、弹窗与网页悬浮窗中出现的正文截断和结构化内容提取不一致问题，确保同一页面从不同入口剪藏时保留相同的完整正文、图片与可识别的媒体链接。

## 已确认现状

- 网页悬浮窗与弹窗的纯文本正文被截断为 3,000 字；侧栏被截断为 5,000 字。
- 三个入口各自实现页面正文和 HTML 元素解析，选择器、图片属性和节点处理规则不一致。
- 当前结构化解析只识别图片，忽略公众号正文中的视频、音频、小程序等嵌入内容；且部分入口会直接丢弃 iframe。
- 当前项目中已有未提交的首用 Markdown、回顾工作流与版本发布修改；本项只新增提取模块并替换提取调用，不回退或覆盖这些修改。

## 方案与组件复用

1. 新增自包含的页面提取模块，作为 `chrome.scripting.executeScript` 的唯一注入函数，并同时供内容脚本直接调用。
2. 该模块统一负责：正文容器选择、可见文本清理、完整 HTML 结构解析、图片懒加载地址、公开视频/音频/小程序链接的降级记录。
3. 扩展现有 `HtmlElementInfo` 与 Markdown/飞书文档渲染，复用现有元素流水线，不新建保存通道。
4. 三个入口只负责调用和展示，保持既有保存模式、元数据、存储与隐私边界不变。
5. 在用户明确授权后，构建 `dist/` 并检查产物不再包含旧的 3,000/5,000 字截断逻辑；Chrome 重新加载的是该目录而非 `src/`。

## 数据与隐私边界

- 所有提取继续在用户当前页面本地执行，不新增网络请求、后端、遥测或 URL/正文上传。
- 嵌入内容仅记录页面已公开展示的标题或链接，用于在导出内容中保留引用；不下载媒体文件。

## 验收标准

- 同一长文章在侧栏、弹窗、网页悬浮窗均不再因 3,000/5,000 字限制而截断正文。
- 三个入口输出的结构化元素遵循同一规则。
- 图片保持 `data-src`、`data-original`、`data-actualsrc`、`data-lazy-src` 等懒加载兼容。
- 视频、音频、小程序等不能内嵌保存的内容至少保留可访问链接或明确占位，不被静默忽略。
- 不执行 npm 构建、测试或预览命令；完成静态差异、类型/导入检查后，要求用户在真实公众号页面重新加载插件验证。
- 如用户提供的真实验证仍命中旧产物，必须先取得构建授权，产物检查通过后才可要求其再次重新加载验证。
