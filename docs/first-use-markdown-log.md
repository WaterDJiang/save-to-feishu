### 实际改动

- 新增共享 `MarkdownFirstSaveCard`，供侧栏和弹窗的“无资料库”状态复用：包含本地 Markdown 主操作、飞书可选设置入口、两步说明与保存结果反馈。
- 侧栏首次状态改为“本地 Markdown 剪藏”，不再把“选择飞书资料库”作为没有配置时的首要任务；完成下载后显示成功反馈并保留既有最近保存记录。
- 弹窗首次状态改为同一张首次保存卡片；保存时先尝试保留网页结构，失败则自动使用已提取文本生成 Markdown。
- 新配置默认保存方式改为 `markdown`。没有 `saveMode` 的旧配置按是否存在资料库兼容：已有资料库保持 `feishu`，没有资料库改为 `markdown`。
- 内容脚本、后台的保存方式兜底值同步改为 `markdown`，防止首次加载短暂回退到飞书模式。
- 设置页将“先保存到电脑”置于默认保存方式首位；帮助弹窗和静态帮助页同步说明“先保存，再按需连接飞书”。

### 关键决策

- 不将飞书配置自动写入、不改变已存在资料库用户的旧保存偏好，也不新增任何网络请求、权限或埋点。
- 首次保存仍复用 `rememberSavedContent`，因此保存成功会进入既有“最近保存与待回顾”中心，并沿用成功保存计数规则。

- `git diff --check`：通过。

- 已检查保存方式默认值、后台消息兜底和内容脚本初始值一致为 `markdown`。
- 按项目规则未运行 `npm test`、`npm run build` 或本地预览。

重新加载插件后需人工验证：

1. 在 `chrome://extensions/` 找到 Save to Feishu，点击“重新加载”。
2. 使用没有任何飞书资料库的新 Chrome Profile 或清除插件本地配置后，打开真实网页并点击插件图标。
3. 确认侧栏和弹窗都先显示“保存 Markdown 到电脑”，无需填写飞书凭证。
4. 点击保存，确认浏览器下载 `.md` 文件、界面显示成功反馈、侧栏“最近保存与待回顾”可看到该记录。
5. 点击“稍后连接飞书”，确认只打开设置页，不会自动写入凭证或发起外部请求。

### 双入口交互修正

用户反馈：首次卡片不应让用户感觉只能在“先保存 Markdown”和“稍后连接飞书”之间二选一；飞书与 Markdown 都是可用保存方式，应同时露出。

实际改动：

- 共享首次保存卡片改为两张同权整行入口卡，而非主次按钮：
  - “保存到飞书”：点击后打开设置页，完成凭证和资料库连接；
  - “保存 Markdown 到电脑”：继续复用原有直接下载与本地保存历史逻辑。
- 两个入口均在侧栏和弹窗的无资料库状态下同时可见；没有配置飞书不会阻止 Markdown 保存。
- 首次卡片、帮助弹窗和静态帮助页统一改为“飞书与 Markdown 都可以”的表述，避免单一路径暗示。

关键决策：

- 在空间受限的侧栏与弹窗中采用上下两张等权卡片，而不是横向压缩按钮；两者同时完整可见，标题、说明和箭头反馈一致。
- “保存到飞书”在未配置状态下不伪造保存成功，只进入真实设置路径；“保存 Markdown 到电脑”保持原有立即下载行为。

验证结果：

- `git diff --check`：通过。
- 已检查侧栏和弹窗的组件属性均改为 `onSaveToFeishu`，不存在旧的 `onConfigureFeishu` 引用。
- 按项目规则未运行 npm 构建、测试或预览。

人工验证更新：

1. 在未配置资料库时打开侧栏和弹窗，确认“保存到飞书”与“保存 Markdown 到电脑”同时完整可见。
2. 点击“保存到飞书”，确认打开设置页面；点击“保存 Markdown 到电脑”，确认直接下载 `.md` 文件。
